# TANJIL Cyber Identity V2.5 Implementation Plan

## Repository assessment

The V2.4 baseline already has PostgreSQL-backed accounts and profiles, public learning guides, visitor statistics, a seven-day reviewed skill event, private/group Socket.IO chats, and basic admin APIs. Database initialization is idempotent and existing tables/columns are extended without dropping data.

The major gaps were: Messenger had replies but no reactions, typing, live presence, or per-message seen receipts; the public profile had no durable rank or achievement feed; the admin API had no owner-facing control center; challenges were limited to the single seven-day event; theme selection was only dark/light on the homepage; `/user/:username` was not served; and the example environment file contained populated bootstrap values.

## V2.5 implementation delivered in this change

- **Messenger 2.0:** added validated message reactions, per-message read receipts, live typing events, and multi-tab-safe online presence. Existing reply, group, and private-chat behavior remains supported.
- **Skill challenges:** added owner-created open/closed challenges, member submissions, HTTPS link validation, review/approval/revision actions, and first-project/project-builder achievements.
- **Ranks and achievements:** added persistent profile ranks and an achievements table; approved seven-day tasks update ranks and award completion achievements. Public profiles now show rank, founder identity, and earned achievements.
- **Owner control center:** added platform analytics, member status/role/rank management, and direct access to both review queues. Privileged roles remain separate from profile ranks.
- **Themes and mobile navigation:** added dark, light, AMOLED, Cyber Blue, and Neon Purple selection across app pages, plus mobile bottom navigation.
- **Compatibility and hardening:** retained the seven-day event and legacy `/u/:username`/query-based public-profile URLs; added canonical `/user/:username`, same-origin checks for browser mutations, a 12-character minimum for bootstrap passwords, and blank bootstrap values in `.env.example`.

## Remaining rollout

1. **Reports and chat moderation:** define report categories, retention policy, moderator permissions, audit history, and appeal flow before enabling message removal or sanctions.
2. **Platform settings and event operations:** persist editable site settings and add owner controls for event schedules, enrollment limits, and rank/achievement definitions.
3. **Project portfolios and achievements:** let members curate/hide approved projects and add achievement triggers for streaks and messaging milestones.
4. **Theme polish:** replace remaining component-specific hard-coded colors with shared design tokens and visually verify every page in all five themes.
5. **Production verification:** add automated PostgreSQL migration/API tests, Socket.IO integration tests, browser coverage for mobile layouts, and load tests for presence, chat history, and admin queries.

## Acceptance criteria

- A clean database boots from `database/schema.sql`; upgrading a V2.4 database adds new tables/columns without deleting existing data.
- Existing login, profile, seven-day event, public-profile query URLs, and private/group chats remain usable.
- Non-members cannot join/read/write a conversation; only admins can create/manage challenges, review work, or change account roles/ranks.
- User-supplied content is rendered as text/escaped markup, and external project/profile links require HTTPS.
- Socket updates remain correct across multiple tabs and reconnects.
- The production checklist above is completed before calling the entire V2.5 roadmap fully production-verified.
